## Non-obvious lesson 1 — channel narrowness
Diligent sub-agent sweep found only **6 publicly verifiable inboxes**
across ~14 candidate brands (CoinSnacks, Wu, Banger Royale, Milk Road,
Dose of DeFi, etc. — all Twitter/Telegram/Substack-form only, no email).
Cold-email is a **narrow channel** for crypto-newsletter operators.

→ If outbound becomes a recurring growth motion, batch 2 should NOT be
"find 5 more emails". It should be a different mechanic: Twitter DM
batch (needs an X account, not currently configured) or Substack
public-comment batch (on-topic reply to their latest post).

## Non-obvious lesson 2 — Resend via Python needs UA header
First attempt: 5/5 → HTTP 403 / Cloudflare error 1010
("browser signature banned"). Root cause: `urllib` default UA
(`Python-urllib/3.x`) is WAF-banned by api.resend.com's Cloudflare layer.
Fix: explicit `User-Agent: web3-discover-agent/1.0 (+url)` header.
Retry: 5/5 → 200. **Curl works first try** (recognized UA).

Fix baked into `product/distribution/_send_outbound_seed_2026_05_11.py`.
Any future Resend-via-Python tooling needs this header.
